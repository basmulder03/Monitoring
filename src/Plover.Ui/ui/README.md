# Dashboard

The dashboard is a TypeScript app on [Preact](https://preactjs.com/) (about 4 KB), bundled by esbuild into `app.js`, `styles.css` and `index.html`. The build of `Plover.Ui` runs `npm ci` and `npm run build`, writes them to `../wwwroot` (not committed) and embeds them in the controller.

```text
src/
  api/contracts.ts       The types of the controller's JSON. GENERATED from the C# records, never edited by hand
  services/              Everything the browser provides (fetch, the live stream, the clock, storage) behind one interface, so tests run against fakes
  state/                 Hooks: the live overview, the route, the theme, what a person opened, JSON loading
  components/            Small pieces used by several views: icons, status, header, banners
  views/overview/        Tiles, groups, filter, alerts
  views/scope/           A scope with its services, instances and containers
  views/dependencies/    The graph: layout (pure and tested), drawing, the table
  styles/                Design tokens first, then one file per area
  start.tsx, main.tsx    Start-up
test/                    Vitest in jsdom; one file per view
```

## Rules

- **Types are the contract.** `contracts.ts` is generated by a test (`tests/Plover.Ui.Tests`) from the C# types. When a C# type changes, that test fails; regenerate with `UPDATE_CONTRACTS=1 dotnet test --project tests/Plover.Ui.Tests` and fix what no longer type-checks.
- **Strict TypeScript**, including `noUncheckedIndexedAccess`. `npm run typecheck` runs in the build.
- **Data from agents is text.** JSX escapes it; `dangerouslySetInnerHTML` and its relatives are forbidden by a test.
- **No inline script or style**, so the content security policy needs no `unsafe-inline`.
- **A state is an icon and a word**, never a colour alone; the design tokens are checked for contrast in both themes.

## Commands

```sh
npm ci            # once
npm run build     # type-check and bundle into ../wwwroot
npm test          # unit tests (also run by dotnet test)
```
